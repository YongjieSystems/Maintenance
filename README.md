# 永捷維修費估價程式 v2.3.0

## 操作說明／教育訓練

登入頁、維修草稿上方及團隊頁皆有「操作說明／教育訓練」按鈕，登入前也能查看。內含 12 個章節的逐步說明，可搜尋關鍵字，或點章節直接查看；「返回原畫面」及 Escape 均可關閉，保留原表單。內容涵蓋登入與角色、新增員工、檢測案件連結、維修報價、同步版本、檢測折抵、主管核准、正式輸出、排線、交接及常見問題。發布根目錄檔案時，請一併發布新增的 `training.js`；Vite 建置會自動包含此檔案。

第二階段加入員工帳號、共用維修版本、主管核准、檢測費折抵及同一案件的集中收送排程。原有價目表、350 元／小時計價及交機加價設定保持不變。

## 團隊日常操作

1. 按「使用員工帳號／團隊作業」或上方「團隊／核准／收送」，使用檢測系統已開通的員工電子郵件與密碼登入。兩套系統共用員工名單；每個分頁仍須確認登入。
2. 有檢測案件時，選擇案件並帶入客戶資料；已有維修版本時，直接按該案「載入維修」，避免另建重複案件。不要把不同客戶連到同一案件。
3. 返回草稿完成設備、故障及費用，再到團隊頁填檢測折抵金額。折抵預設為 0，不會擅自改成免費檢測。
4. 按「同步目前維修草稿」。伺服器使用原有核定價目重新計算，保存版本；本機自訂價目不會改寫公司共用價目。畫面會顯示原檢測費、折抵、重疊收送扣除、案件合計與待收參考。
5. 沒有檢測案件時，可直接同步成新的共用維修案件。選到店或收送；收送須填約定時段與範圍。已連結檢測案件的服務方式沿用原設定，要變更請先更新檢測案件。
6. 主管先核准檢測報價，再填「主管核准理由」及「客戶同意方式與時間」，核准目前維修版本。直接建立的維修案件由維修核准入口處理。正式維修金額必須是確認的單一金額，不能仍是價格區間。
7. 只有最新檢測及維修版本都有效核准，客服或主管才能「複製正式報價」或「下載正式報價」。下載 HTML 後可開啟並列印。每次輸出都重新向後端檢查核准，不以按鈕顏色當作授權。
8. 在同一頁的「集中排線」選該案件，依序安排取件、回送及人員。主管發布路線；收送人員只讀自己的已發布任務並依序回報。系統檢查衝突與重複任務，不自動計算最佳交通路線。

修改維修價格、折抵或檢測報價後，需要重新同步及核准。回送路線發布與完成回報都會檢查最新維修核准；已有回送完成或已結案的案件不能再改價，請另建新案。

## 費用整合方式

案件合計 ＝ 原檢測報價（含原收送）＋ 維修小計 − 核准檢測折抵 − 重疊收送扣除。

例如：原檢測 500 元＋收送 300 元，維修小計 1,000 元（其中也列收送 300 元），主管核准檢測折抵 500 元，則合計為 800＋1,000−500−300＝1,000 元。這是在避免兩張報價重複計費，沒有調整原價目。

檢測折抵不得超過原檢測報價扣除原收送的金額；重疊收送扣除為兩邊已列收送費的較小值。既有檢測已收金額只作待收參考，請核對公司收款紀錄；本功能不執行扣款、退款或會計入帳。

## 員工權限

- 主管：管理員工、核准報價／折抵、分派工程師、發布及取消路線。
- 客服／行政：建立及同步報價、檢視共用版本、編排路線草稿，不能核准。
- 工程師：只讀分派案件及自己的已發布任務；不能核准報價。
- 收送人員：只取得自己的已發布路線及交接資訊，不取得維修金額版本。

新增員工仍由主管在「員工名單與權限」登錄，再為新帳號產生一次性連結，由員工本人設定密碼。停用後，即使舊登入尚未到期，後端也會拒絕資料與操作。

## 員工操作

1. 按「使用員工帳號／團隊作業」，以啟用中的主管或客服／行政帳號登入。
2. 按「＋ 新案件」，依序選設備類型、設備分類與故障問題。
3. 檢查預估零件費、工時、運費；必要時填額外費用及說明。
4. 填客戶、序號、報價人員及備註。畫面上的「可能處理」是參考項目，檢測前不代表一定需要更換。
5. 若直接修改總額，與原明細的差額會列為「報價調整」。有差額時必須填調整原因；單一金額仍屬待客戶確認的估價。
6. 按「儲存報價」。複製摘要、Excel、儲存並列印也會保存目前版本；若內容沒變，重複操作不會增加版本。
7. 下一位客戶請按「＋ 新案件」，避免沿用上一位客戶資料。尚未儲存的內容會先詢問是否放棄。

金額不可為負數，最高價不得低於最低價，折扣不得超過最低費用小計，金額最多兩位小數。紅色提示存在時，儲存及匯出按鈕會停用；請先修正提示內容。

## 案件與備份

- 「估價紀錄」保存同一案件的各個報價版本；修改已儲存案件後再儲存，會建立新版本。舊版本保持可複製、匯出。
- v2.1.0 新增紀錄支援「載入編輯」；先前舊紀錄沒有完整表單資料，仍可複製與匯出。
- 不再自動截掉第 50 筆以外的紀錄，但瀏覽器儲存空間仍有限。
- 「案件備份」下載 JSON 檔，包含價目表及已儲存報價版本，不包含尚未儲存的畫面內容。
- 「還原案件」選擇案件備份 JSON，會合併缺少的紀錄，保留目前已有的案件、版本及價目表；相同單號與版本以目前已有資料為準。此操作不匯入備份內的價目表。
- 「資料庫管理 → 價目表備份」只下載價目表 JSON，不是整套可離線執行的 APP，也不包含歷史案件。
- 請定期備份。資料只存在目前瀏覽器，換電腦或清除網站資料不會自動恢復。儲存失敗時會顯示提示並停止列印。

本機草稿與本機歷史不會自動上傳。已取消共用密碼，估價必須使用員工帳號；公司正式核准、折抵及收送必須經員工登入與後端檢查。共用列表每 15 秒更新，保存時核對版本，避免覆寫同事修改。

## 開發與部署

需要 Node.js 及套件管理工具；本程式不需要 Gemini API 金鑰。

```sh
pnpm install
pnpm test
pnpm build
pnpm dev
```

開發網址為 `http://127.0.0.1:4175/`。`index.html` 保留既有瀏覽器 Babel 架構，計價與驗證集中在 `repair-core.js`，響應式樣式在 `interface.css`。

GitHub Pages 從原有根目錄發布時，必須一起發布 `index.html`、`interface.css`、`repair-core.js`、`repair-team.js`、`team-workspace.js`、`team-config.js`、`team-core.js` 及 `vendor/supabase.js`。若改用建置產物，部署完整 `dist/`。React、Tailwind、Babel、Excel 套件等仍使用既有外部 CDN，使用時需要網路。前端僅使用 publishable key；角色、核准、計價及站點規則在資料庫執行，沒有前端 service role key。

測試涵蓋原始價目表不變、上下限與負數驗證、手動調整差額、案件版本、重複匯出、歷史載入、備份合併、儲存失敗及交機加價。

## 員工登入與密碼恢復（2026/10/21）

三套估價使用同一組已開通的員工帳號，各網站分別登入。估價僅主管及客服／行政可用；保固與驅動查詢保持公開。維修共用密碼入口已取消，助理口頭確認後可直接輸出客戶報價，團隊正式版、折抵及排線仍沿用原核准規則。

忘記密碼：填正確信箱 → 寄送重設信 → 在本人信箱開啟最新連結 → 設定至少12字元的新密碼。主管可在員工名單寄送重設信、調整角色或停用；不會看到密碼，也不取得員工的登入連結。重設返回網址固定為正式檢測網站，部署時 Supabase Site URL 與允許清單須包含該網址。


### 登入保存方式
登入頁可選「保持登入 24 小時」（預設）、「記住這台電腦 30 天」或「共用電腦／僅本次登入（目前分頁）」。24 小時與 30 天從登入成功起固定計算，重新開啟網頁會恢復登入，憑證自動更新不延長期限。僅本次登入不將憑證保存至 localStorage；重新整理可保留，關閉分頁後一般需重新登入（瀏覽器還原分頁可能保留分頁儲存）。個人專用電腦才使用 30 天。按「登出／清除記住登入」會清除此程式在本瀏覽器的保存，原有報價備份不變。清除網站資料、無痕模式、後端撤銷憑證或停用員工也可能要求重登。

三套程式各自保存期限及登入選擇，不將密碼寫入程式，也不將登入憑證加入報價備份。舊版分頁登入只遷移為本次登入；必須由員工下次登入時自行選擇較長期限。期限屬於瀏覽器保存政策，Supabase 驗證、啟用員工檢查及資料庫權限照常執行，未修改後端 JWT 有效期。到期時立即關閉估價與共用資料入口並清除保存憑證，未保存的報價內容仍需員工自行保存。
